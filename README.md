# 식단 달력

날짜별 섭취 칼로리를 기록하는 달력. https://namyikim.github.io/diet

- 달력의 각 날짜에 아침·점심·저녁·간식 칼로리와 하루 합계가 표시됩니다.
- 날짜를 누르면 바로 칼로리 입력 칸에 커서가 놓입니다. 칼로리와 먹은 것을 적으면 입력하는 즉시 저장됩니다.
- `+` 로 한 끼에 여러 줄을 추가할 수 있습니다(간식 여러 번 등). Enter 로 다음 칸 이동.

## 저장 방식

서버 대신 **비공개 GitHub 저장소의 `data.json`** 에 저장합니다. 페이지가 GitHub API로 직접 읽고 쓰므로
여러 휴대폰·컴퓨터에서 같은 기록을 봅니다.

1. 비공개 저장소를 하나 만듭니다 (예: `diet-data`, 비어 있어도 됨).
2. Fine-grained 토큰을 발급합니다 — Repository access: 그 저장소만, Permissions: **Contents → Read and write**.
3. 페이지 하단 **동기화 설정**에 저장소 이름과 토큰을 넣고 연결합니다.
4. 다른 기기는 **연결 키**로 연결합니다 — 연결된 브라우저의 동기화 설정에서 "안전한 연결 키 만들기"로 만든 암호문을
   **공개 GitHub Pages 저장소(`namyikim/diet`)**에 `connect.json`으로 올려 두면, 새 브라우저에서 연결 키만 입력할 수 있습니다.
   식단이 저장되는 비공개 `diet-data` 저장소가 아니라 사이트 코드가 있는 공개 저장소입니다.
   토큰은 PBKDF2-SHA256 60만 회 + AES-GCM으로 암호화됩니다. 암호문이 공개되므로 연결 키는 반드시 16자 이상으로 설정합니다.

- 복호화된 토큰은 `sessionStorage`에만 보관되어 브라우저를 닫으면 제거됩니다. 다시 열 때 연결 키를 입력합니다.
- 토큰 원문을 URL에 담는 기기 공유 링크는 제공하지 않습니다.
- 입력은 먼저 기기에 저장되고 2초 뒤(또는 완료를 누르는 즉시) 서버로 올라갑니다. 오프라인이면 연결될 때 올립니다.
- 두 기기가 동시에 서로 다른 끼니를 고치면 끼니별 논리 revision으로 병합되어 양쪽 변경이 함께 남습니다.
- 페이지 하단의 백업 파일 저장/불러오기는 그대로 쓸 수 있습니다.

> 이전 버전에서 만든 `connect.json`과 PAT를 사용했다면 새 PAT를 발급해 교체하는 것을 권장합니다. 공개 저장소의 과거 커밋에는
> 이전 암호문이 남아 있을 수 있습니다. 또한 비공개 데이터 저장소의 `data.json`은 현재 암호화되지 않으므로 저장소 접근 권한과
> Git 커밋 기록을 식단 기록 보관 범위로 간주해야 합니다.

배포 후에는 열려 있던 모든 기기의 페이지를 새로고침해 새 병합 형식을 사용하세요. 기존 `t` 형식 데이터는 자동 변환됩니다.

## 구조

- `index.html`, `style.css`, `app.js`: 화면과 브라우저 동작
- `core.js`: 데이터 정제, 끼니별 병합, 직렬화
- `connect.json`: 선택 사항인 암호화 연결 정보
- `tests/`, `.github/workflows/test.yml`: Node 기본 테스트와 CI

빌드 과정이나 런타임 의존성은 없습니다. 로컬 테스트는 다음 명령으로 실행합니다.

```bash
npm test
```

## 배포

GitHub → Settings → Pages → Source: `Deploy from a branch`, Branch: `main` / `(root)`.
